# 工賃シミュレーター 画面設計書（MVP）

## 1. 目的・前提

本書は、[工賃シミュレーター 要件定義書（仮）v0.5](./要件定義書_工賃シミュレーター_仮_v0.5.md)に基づくMVPの画面設計を定める。

MVPは、利用者と職員が一緒に操作し、その日の工賃概算を確認するためのシミュレーターである。計算結果・個人情報・入力内容は保存しない。

画面構成は、**縦型1画面＋下部固定の合計表示＋「つかいかた」オーバーレイ**を基本とする。

## 2. 画面一覧

実質的に1画面と補助ビューで構成する。

| ID | 画面・ビュー | 種別 | MVP |
|---|---|---|---|
| SC-01 | 工賃計算メイン画面 | メイン画面 | 必須 |
| OV-01 | つかいかたビュー | モーダル／サイドパネル | 必須 |
| STATE-01 | やさしい表示 | SC-01の表示状態 | 必須 |
| STATE-02 | 出来高追加 | SC-01内の部品追加 | 必須 |
| STATE-03 | 計算結果 | SC-01内のリアルタイム表示 | 必須 |
| STATE-04 | リセット確認 | 小さな確認表示 | 必要に応じて実装 |

MVPのURLは `/` のみで成立させる。ページ遷移は原則発生させない。

## 3. 画面全体レイアウト

### 3-1. 基本構造

```text
┌─────────────────────────────┐
│ 今日の工賃を計算              │
│ [やさしい表示] [？つかいかた] │
├─────────────────────────────┤
│ ① 午前                        │
│   業務・時間・能力加点         │
│   午前の工賃                   │
├─────────────────────────────┤
│ ② 午後                        │
│   業務・時間・能力加点         │
│   午後の工賃                   │
├─────────────────────────────┤
│ ③ 出来高                      │
│   出来高入力（複数追加可能）    │
├─────────────────────────────┤
│ 今日の工賃（下部固定）         │
│ 午前 + 午後 + 出来高 = 合計    │
│ [おわる・入力をリセット]       │
└─────────────────────────────┘
```

午前→午後→出来高→合計の順に、業務の流れに沿って上から配置する。PCでもモバイルでも基本順序と操作位置を大きく変えない。

### 3-2. レイアウト方針

- 午前・午後・出来高を独立したカードとして視覚的に分ける
- 入力項目と計算結果を同じカード内で確認できるようにする
- 合計は下部に固定表示し、入力中も見失わないようにする
- PCで無理に左右2列へ分割しない
- 入力項目を折りたたまない（MVPでは認知負荷を増やさない）
- 出来高追加は別ページではなく同じ画面に欄を追加する

## 4. SC-01 工賃計算メイン画面

### 4-1. ヘッダー

| 項目 | 仕様 |
|---|---|
| 画面タイトル | 今日の工賃を計算 |
| やさしい表示 | 同一画面内で表示文言を切り替える |
| つかいかた | `？ つかいかた` を押してOV-01を開く |
| 保存表示 | 保存しないことを必要に応じて説明する |

初期タイトル例：`今日の工賃を計算`。やさしい表示では `きょうの こうちんを けいさん` 等の平易な文言を候補とする。

### 4-2. AMカード

```text
① 午前

しごと
[ KIIYA ▼ ]
1時間 150円

はたらいた時間
[ 2 ] 時間  [ 30 ] 分

加点
[ 100円 ▼ ]

午前の工賃                    475円
```

#### 項目仕様

| 項目 | 入力・表示 | 必須 |
|---|---|---:|
| 業務 | 業務選択式 | 未入力可（作業なし対応のため） |
| 業務別時給 | 選択業務に応じた表示専用 | — |
| 時間（時） | 数字入力 | 業務選択時 |
| 時間（分） | 数字入力 | 業務選択時 |
| 能力加点 | 現行加点から選択 | 業務選択時 |
| 午前の工賃 | 自動計算・表示 | — |

業務を選択すると業務別時給を表示する。時間と加点が変更されるたびに午前工賃を再計算する。

### 4-3. PMカード

AMカードと同じ構造を持つ。午前と午後で別々の業務、時間、能力加点を入力できる。

```text
② 午後

しごと
[ PC ▼ ]
1時間 100円

はたらいた時間
[ 3 ] 時間  [ 0 ] 分

加点
[ 100円 ▼ ]

午後の工賃                    400円
```

### 4-4. 出来高カード

```text
③ 出来高

出来高 1
なまえ
[ シール貼り                 ]

1個あたり
[ 10 ] 円

数量
[ 20 ]

小計                         200円
[ この出来高を削除 ]

[ ＋ 出来高を追加 ]
```

#### 項目仕様

| 項目 | 入力・表示 | 必須 |
|---|---|---:|
| 出来高名 | 自由記述 | 未確定（プロトタイプ確認） |
| 単価 | 数字入力 | 追加行ごとに設定 |
| 数量 | 数字入力 | 追加行ごとに設定 |
| 単位 | 未確定 | MVPでは任意表示候補 |
| 小計 | `単価 × 数量` の自動計算 | — |
| 削除 | 現在の画面状態から行を削除 | — |

「＋ 出来高を追加」を押すと、同じ画面内に出来高2、出来高3の入力行を追加する。追加数の上限は、極端な画面肥大化を防ぐため実装時に定める。

### 4-5. 合計表示

```text
今日の工賃

午前                         475円
午後                         400円
出来高                       200円
────────────────────────
合計                       1,075円

[ おわる・入力をリセット ]
```

合計は常に画面下部へ固定表示する。固定表示が入力欄を隠す場合は、入力欄に十分な下部余白を設ける。

表示式は次のとおり。

```text
合計 = 午前工賃 + 午後工賃 + 出来高合計
```

計算結果は入力変更時に即時更新する。円未満の端数が発生した場合は、金額を円単位で切り上げる。AM/PMごと、出来高合計、日額合計のどの単位で切り上げるかは、計算仕様と実例確認に基づいて確定する。

## 5. 入力状態と表示状態

### 5-1. 初期状態

- 午前・午後の業務は未選択
- 時間は空欄または0
- 能力加点は「なし」
- 出来高入力欄は1件表示するか、追加ボタンのみ表示するかをプロトタイプで確認
- 合計は0円または未入力状態として表示

### 5-2. 入力中

- 入力値が変わるたびに該当小計と合計を更新
- 不正値がある場合は該当欄の近くに短いエラーを表示
- 不正値を合計へ反映しない
- `NaN`、`Infinity`、空の計算結果を表示しない

### 5-3. 作業なし

午前または午後に作業しない場合の表示は未確定。候補は「作業なし」を選択し、そのカードの工賃を0円とする方式。

### 5-4. リセット確認

「おわる・入力をリセット」を押した際、誤操作防止のため確認表示を出すかは実装時に決める。確認を出す場合も小さな確認表示とし、入力状態を維持したままキャンセルできるようにする。

## 6. 操作仕様

| 操作 | 結果 |
|---|---|
| 業務を選択 | 業務別時給を表示し、計算へ反映 |
| 時間を入力 | AMまたはPMの工賃と合計を再計算 |
| 能力加点を選択 | AMまたはPMの工賃と合計を再計算 |
| 出来高を入力 | 該当小計と出来高合計を再計算 |
| 出来高を追加 | 同じ画面に新しい入力行を追加 |
| 出来高を削除 | 該当行を画面から除去し、合計を再計算 |
| やさしい表示 | 同じ画面の文言・表示状態を切替 |
| つかいかた | OV-01を開く。入力値は保持 |
| おわる | 入力値・計算結果を破棄して初期状態へ戻す |

## 7. OV-01 つかいかたビュー

### 7-1. 表示方式

モーダルまたはサイドパネルとする。完全なページ遷移は行わない。

```text
┌────────────────────┐
│ このアプリのつかいかた │
│                    │
│ ① ごぜんのしごとをえらぶ │
│ ② はたらいたじかんをいれる │
│ ③ ごごのしごとをえらぶ   │
│ ④ できたかずをいれる     │
│ ⑤ きんがくをかくにんする │
│                    │
│ [ とじる ]          │
└────────────────────┘
```

### 7-2. 要件

- 計算画面からいつでも開ける
- 開いている間も入力状態を保持する
- 「とじる」で元のスクロール位置・入力状態へ戻る
- 説明は短く、1ステップ1メッセージを基本とする
- 背景クリックだけで閉じる仕様にする場合は、誤操作を考慮して確認する
- キーボード操作時は開いたビューへフォーカスを移し、閉じた後に元のボタンへ戻す

## 8. やさしい表示

### 8-1. 切替

ヘッダーの「やさしい表示」スイッチまたはボタンで、同じ画面の文言だけを切り替える。画面構造・入力順・操作位置は原則変えない。

### 8-2. 表示例

| 通常表示 | やさしい表示 |
|---|---|
| 今日の工賃を計算 | きょうの こうちんを けいさん |
| 午前 | ごぜん |
| 午後 | ごご |
| 作業時間 | はたらいた じかん |
| 能力加点 | くわえる おかね |
| 出来高 | できた かず |
| 合計 | ぜんぶで |
| おわる・入力をリセット | おわる・はじめにもどる |

具体的な表示文言はプロトタイプを利用者・職員に確認して確定する。

## 9. ルビとレスポンシブ表示

### PC等の広い画面

- 通常表示では必要な漢字にルビを表示できる
- やさしい表示では原則として漢字を減らし、平仮名・平易な表現にする

### モバイル等の狭い画面

- 通常表示では表示領域を圧迫するためルビの多用を避ける
- やさしい表示では平仮名中心とする

ルビ表示のブレークポイントは未確定。表示用テキストは自動変換せず、名称・読み・やさしい表示文言を個別に管理する。

## 10. アクセシビリティ・UI基準

- 白をベース、緑をアクセントとする
- 色だけで状態やエラーを表現しない
- 選択状態は `✓ 選択中` 等の文字・形・色を併用する
- 本文は18〜20px以上、やさしい表示は20〜24px程度を暫定基準とする
- ボタン・入力欄は44〜48px以上を基本とする
- 行間は1.5以上を基本とする
- アイコンだけの操作を避け、文字ラベルを併記する
- 金額・時間は「150円 / 時間」「2時間30分」のように省略せず表示する
- 入力フォーカスを明確にする
- キーボードだけでも主要操作が可能な構造にする
- 文字拡大時に入力欄・固定合計・ボタンが重ならないようにする
- 共有端末で前の入力が残らないことを最優先する

## 11. エラー表示

エラーは入力欄の近くに、何を直せばよいか分かる短い文で表示する。

| 状況 | 表示例 |
|---|---|
| 数字以外 | 数字をいれてください |
| 負数 | 0以上の数をいれてください |
| 上限超過 | 大きすぎる数です |
| 時間の分が不正 | 0〜59分でいれてください |
| 単価・数量が空欄 | 単価と数量をいれてください |
| 計算対象が未入力 | 入力すると金額が表示されます |

エラー時も画面全体をリセットしない。未入力は状況に応じて0円として扱うか、未入力表示とするかを計算仕様と合わせて決定する。

## 12. 計算ロジックとの接続

画面コンポーネントへ計算式を直接埋め込まず、計算処理を分離する。

```text
画面入力
  ↓
入力値の検証
  ↓
CalculationEngine
  ↓
計算結果（AM / PM / 出来高 / 合計）
  ↓
画面表示
```

業務別時給・能力加点は設定ファイルから読み込む。MVPでは設定編集・DB保存・API通信は行わない。

## 13. 画面内状態モデル（暫定）

```text
calculatorState
├ am
│  ├ workItem
│  ├ hours
│  ├ minutes
│  └ bonus
├ pm
│  ├ workItem
│  ├ hours
│  ├ minutes
│  └ bonus
├ pieceworks[]
│  ├ name
│  ├ unitPrice
│  ├ quantity
│  └ unit（未確定）
└ easyDisplay
```

この状態はメモリ上だけで管理し、リロード・ページ終了・リセットで破棄する。

## 14. 画面遷移

```text
[アプリ起動]
      ↓
[SC-01 工賃計算画面]
      ├─ 午前入力
      ├─ 午後入力
      ├─ 出来高入力
      │    └─ [+ 出来高を追加] → 同じ画面に欄追加
      ├─ [やさしい表示] → 同じ画面の文言変更
      ├─ [? つかいかた] → [OV-01] → [閉じる] → SC-01
      └─ [おわる] → 入力初期化 → SC-01初期状態
```

## 15. MVP外の将来画面

現MVPでは作成しない。永続化や正式記録へ方針変更した場合に再設計する。

- 工賃設定画面
- 利用者選択・利用者管理画面
- 過去の工賃履歴・結果詳細画面
- 職員ログイン・管理画面
- バックアップ・復元画面

将来拡張時には、認証、個人情報、DB、保存期間、権限、監査ログを新たに要件定義する。

## 16. プロトタイプ確認事項

次の確認結果で画面構造を確定する。

- 午前中に2種類以上の業務をする日があるか
- 午後中に2種類以上の業務をする日があるか
- 午前または午後に作業しない場合、「作業なし」でよいか
- 15分など1時間未満の作業時間をどう入力・計算するか
- 出来高の単位（個、枚、セット、回等）を表示する必要があるか
- 出来高名を毎回入力する必要があるか
- A〜Fの能力区分を利用者へ表示して問題ないか
- 下部固定の合計表示が入力の邪魔にならないか
- 「おわる」押下時に確認表示が必要か

特に、**AM/PMそれぞれで複数業務を行うか**は、カード構造を変更する可能性が最も高い。

## 17. MVP受入条件

### 計算・入力

- [ ] 午前と午後で別々の業務を選択できる
- [ ] 業務選択に応じた時給が表示される
- [ ] 午前・午後の時間と能力加点を別々に入力できる
- [ ] 出来高を複数追加できる
- [ ] 各出来高について単価×数量を計算できる
- [ ] 出来高をその場で削除できる
- [ ] AM＋PM＋出来高が合計表示される
- [ ] 入力変更時に即座に再計算される
- [ ] 不正な数値入力を計算値へ反映しない

### データ保護・リセット

- [ ] DBへ入力内容・計算結果を保存しない
- [ ] localStorage、IndexedDB、Cookieへ工賃データを保存しない
- [ ] 「おわる」で全入力を初期化する
- [ ] 次の利用者へ前の入力内容・計算結果が残らない
- [ ] ページリロード後に前の入力内容が復元されない

### UI・アクセシビリティ

- [ ] 利用者と職員が同じ画面で操作できる
- [ ] 縦型カード構成で午前→午後→出来高の順に操作できる
- [ ] 合計が下部固定表示される
- [ ] やさしい表示へ同一画面内で切り替えられる
- [ ] PC通常表示で必要なルビを表示できる
- [ ] モバイルで平仮名中心の表示ができる
- [ ] 「つかいかた」を入力途中でも開ける
- [ ] 「つかいかた」を閉じると入力状態へ戻れる
- [ ] 出来高を複数追加・削除できる
- [ ] 工賃合計が明確に見える

## 18. 設計上の未確定事項

| 項目 | 設計への影響 |
|---|---|
| AM/PM内の複数業務 | AM/PMカードを繰り返し入力部品へ変更するか |
| 時間の入力・計算単位 | 時間・分入力、丸め、計算エンジン |
| 小数円の扱い | 金額表示・計算結果 |
| 出来高数量の小数可否 | 数値バリデーション・入力欄 |
| 出来高単位 | 単位選択欄または自由記述欄 |
| 出来高名称の必須性 | 出来高カードの入力項目 |
| 能力加点の表示名称 | 利用者向けラベル |
| 作業なしの表示 | AM/PMカードの初期・未入力状態 |
| 固定合計の表示方法 | モバイルでの重なり・スクロール |
